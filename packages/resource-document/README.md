# @oaknational/resource-document

Application-agnostic contracts for representing extracted educational resource
documents. The package owns the versioned Zod schemas, validation, document
traversal, extraction-markup conversion and rights-safe conformance fixtures.

## Experimental contract

The package remains private at npm version `0.0.0` while ORA is its only
consumer. In future, we may move it to its own repository and publish it for
wider consumption.

The input markup grammar and canonical JSON schema are independently versioned;
both are currently `"0.1"`. `worksheet.v0` and `generic.v0` are experimental
profiles. All may change incompatibly before production use.

Extraction producers should start with the
[extraction handoff contract](EXTRACTION_HANDOFF.md). It identifies the exact
markup document, executable example, supported grammar and output acceptance
rules. Canonical JSON is generated by this package, not by the extractor.

Existing `"0.x"` markup and schema versions may be changed directly during the
pre-production spike. Once ORA needs persisted compatibility or another
consumer depends on the package, incompatible changes receive a new version and
an explicit migration where required.

## Entry points

- `@oaknational/resource-document` — schemas, parsing and traversal helpers.
- `@oaknational/resource-document/markup` — the provisional extraction-markup
  parser.
- `@oaknational/resource-document/fixtures` — rights-safe fixture manifest and
  loader.

The markup grammar is intentionally narrow until real extraction samples are
available. Unknown directives become explicit unsupported nodes and diagnostics;
they are never silently discarded or interpreted as styling.

## Updating the document schema

The versioned Zod model is the source of truth.

For a pre-production refinement of the current experimental contract:

1. Update `src/schema/versions/v0_1.ts`. Put cross-document rules that Zod
   cannot express locally in `src/invariants.ts`.
2. Update parsing, markup conversion and traversal code when the changed shape
   affects those boundaries.
3. Add or update focused tests and the rights-safe conformance fixture. Fixture
   output changes should be reviewed as contract changes, not accepted as
   incidental snapshots.
4. Run:

   ```sh
   pnpm test
   pnpm type-check
   pnpm lint
   ```

When compatibility becomes a requirement, do not change a frozen version in
place: create the next schema or markup grammar version, retain required old
readers, and add explicit canonical JSON migrations. Schema versions describe
the JSON wire contract; markup versions describe extraction syntax. Both are
independent of the npm package version and profile names such as `worksheet.v0`.

## Current profile boundary

`generic.v0` permits the common semantic node vocabulary with minimal metadata.
`worksheet.v0` adds worksheet metadata. Profiles validate resource semantics
only. Applications decide which
transformations, persistence operations, renderers and user controls apply.
